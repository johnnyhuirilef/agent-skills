Load when: writing or reviewing an Entity, an internal aggregate entity, entity identity, or the domain/DAO split.

# Entity Patterns

Rules: `ENT-1` to `ENT-11` in `hard-rules.md`. Kernel `Entity` is in `base-classes.md`.

## Identity types

All identities are Value Objects, including local ids of internal entities. Choose by context:

| Kind | Use when | Example |
|---|---|---|
| Application-generated | Default. Id created before persistence through `IdGenerator` | `new OrderId(deps.idGenerator.generate())` |
| Natural | The real world guarantees uniqueness | `Iban`, social security number |
| Composite | Several values form one identity | `ProductId.of(sku, ean, storeCode)` (see `value-object-patterns.md`) |

A database-assigned id (auto-increment, `@PrimaryGeneratedColumn`) never enters the domain. The DAO may keep a surrogate column, but the domain id is supplied by the application.

```typescript
class BankAccountId extends ValueObject<string> {
  constructor(value: string) {
    super(ensureNonEmpty('BankAccountId', value));
  }
}
```

## Entity shape

```typescript
class ClientApp extends Entity<ClientAppId> {
  private constructor(
    id: ClientAppId,
    private readonly name: string,
    private readonly secret: ClientSecret,
  ) {
    super(id);
  }

  static create(name: string, secret: ClientSecret, deps: DomainDeps = systemDeps): ClientApp {
    return new ClientApp(new ClientAppId(deps.idGenerator.generate()), name, secret);
  }

  static restore(snapshot: { id: string; name: string; secret: string }): ClientApp {
    return new ClientApp(new ClientAppId(snapshot.id), snapshot.name, new ClientSecret(snapshot.secret));
  }
}
```

## Immutable update

Return a new instance instead of mutating. The identity is preserved, so the result is the same Entity.

```typescript
withRotatedSecret(newSecret: ClientSecret): ClientApp {
  return new ClientApp(this.id, this.name, newSecret);
}
```

Use this style for small entities. For entities inside an Aggregate, mutating private fields through validated methods is equally valid (`ENT-5`).

## Domain / infrastructure split

The domain class and the persistence mapper are different classes in different layers.

```typescript
// domain/model/bank-account.entity.ts
class BankAccount extends Entity<BankAccountId> {
  private constructor(
    id: BankAccountId,
    private isLocked: boolean,
    private wallet: Wallet,
  ) {
    super(id);
  }

  static restore(snapshot: { id: string; isLocked: boolean; wallet: WalletPrimitives }): BankAccount {
    return new BankAccount(new BankAccountId(snapshot.id), snapshot.isLocked, Wallet.fromPrimitives(snapshot.wallet));
  }

  deduct(other: Wallet): void {
    if (this.isLocked) throw new DomainBusinessError('Account is locked');
    this.wallet = this.wallet.deduct(other);
  }
}

// infrastructure/adapter/database/bank-account.dao.ts
@Entity()
class BankAccountDAO {
  @PrimaryColumn() id: string; // supplied by the domain, never generated by the database
  @Column({ name: 'is_locked' }) isLocked: boolean;
  @Column('json') wallet: WalletPrimitives;

  toDomain(): BankAccount {
    return BankAccount.restore({ id: this.id, isLocked: this.isLocked, wallet: this.wallet });
  }
}
```

When flagging a TypeORM `@Entity()` on a domain class, cite this quote: *"In TypeORM, the Entity is used as a mapper to a table in the database, but that is not the case with the Entity from DDD. If you use DDD Entity to map it to the database, that is a cardinal error."*

## Pushing logic out of the Entity

Only when a rule spans several Entities or has no natural home, move it to a Domain Service (`domain-service-and-testing.md`). A rule about one Entity's own state stays in that Entity.
